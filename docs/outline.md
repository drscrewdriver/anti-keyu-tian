# 大纲：田柯宇事件中「修改环境相关动作」的指纹防御

> 状态：v0.1 骨架 / 2026-10-23
> 定位：防守方视角。不重复事件八卦，只回答一件事——**当有人在你信任的训练环境里动手，你能靠什么痕迹抓到它、并让它改不动。**
> 素材：https://keyu-tian-sabotage.github.io  及该页引用的一手报道。

---

## 0. 口径先行（术语定义，写死再动笔）

| 术语 | 本文定义 | 说明 |
|---|---|---|
| 环境（env） | 训练任务真正依赖的**可信基座**：容器镜像、已安装的框架库（site-packages）、驱动、共享存储、启动脚本 | 不含"项目代码"——项目代码天然可改，不构成可信基座 |
| 修改环境 | 对该基座的**越权变更**：就地替换已安装库、还原元数据、改启动钩子、埋持久化 | 与正常 install/upgrade 的区别是**没有版本记录、没有审批痕迹** |
| 拍拓 | 对环境的**取证式快照/拓印**：镜像 digest、文件树哈希、inode 元数据、进程与挂载视图 | 变更前后各拓一次，差异即为现场 |
| 指纹 | 变更动作**无法完全抹除**的残留：inode ctime、overlay 白障、审计日志、运行时行为偏差 | 核心论点：mtime 可还原，ctime 不行 |

**一句话论点**：本案攻击者已具备"还原 mtime / 改属主 / 改权限"的反取证意识，但**仍停在文件属性层**；防御的杠杆点不在 `ls -l`，而在 **inode 元数据 + 挂载层差异 + 运行时审计** 这三处他改不到的地方。

## 2. 威胁模型（为什么这类攻击特别难防）

- **对手在信任边界内**：有合法登录、有共享盘读写权、有排查会议席位
- **故障伪装成随机**：纳秒种子、按 rank 取模、2⁻¹⁸ 级概率触发，不可复现
- **跨层组合**：文件层（替换库）+ 概率层（部分 rank）+ 持久层（checkpoint / init.py）+ 通道层（共享盘回执）
- **反馈闭环**：参会获知排查方向 → 反向调整攻击面（这一条决定了防御必须是"流程"而非"工具"）
- **不可疑原则**：被改的是系统库里已安装的 torch，不是项目仓库，代码 review 看不见

明确不覆盖：外网 APT、供应链投毒（那是另一条线）。

## 3. 攻击动作谱系 × 指纹特征（本文的主表）

每行：**动作 → 表层现象 → 反取证处理 → 仍留下的指纹 → 可落地的检测点**

### 3.1 依赖层：site-packages 内 PyTorch 源码就地替换
- 手法：`sudo mv/chown/chmod` 覆盖已安装 torch 文件，随后 `os.utime` 还原 atime/mtime
- 抹掉了：mtime、属主、权限位
- **仍留下**：inode **ctime 无法回写**（Linux 无 setctime 接口）→ mtime < ctime 的倒挂；inode 号变化；overlayfs upper 层出现同路径副本；容器镜像 digest 与实际文件树不符
- 检测点：文件树 Merkle 基线 + ctime 倒挂扫描 + 镜像 digest vs 容器内实测

### 3.2 数据种子层：`DistributedSampler` 换时间种子
- 手法：`g.manual_seed(time.time_ns() % 10000000000)` 取代 `self.seed + self.epoch`
- **指纹**：同 seed 两次运行的 rank→index 映射不一致；源码中出现 `time.` 作随机源
- 检测点：确定性回归测试（同 seed 复跑比对 index 哈希）+ 静态规则扫描 `manual_seed(time.*)`

### 3.3 训练数值层：maximize / clip×2 / nan_to_num
- 手法：`group["maximize"]=True`；`clip_coef.mul_(2)` 但返回正常 norm；load 时 NaN→0；只在部分 rank 生效
- **指纹**：梯度 norm 与实际更新步长不自洽；各 rank 副本在梯度已同步下互相发散；权重出现异常大量精确 0
- 检测点：梯度范数交叉校验（独立计算 vs 框架上报）+ 跨 rank 参数 diff + NaN/0 分布告警

### 3.4 集合通信层：概率性"假装不在组里"
- 手法：`_rank_not_in_group(...) or torch.all(rand(18) < 0.5)`，文件 18/19/20/21 对应不同概率
- **指纹**：集合通信超时/卡死与硬件健康度不相关；失败集中在特定 shape/步数区间
- 检测点：通信层心跳与 rank 活跃度矩阵 + 卡死前 N 步的 rank 集合快照

### 3.5 进程层：定向 pkill
- 手法：`pkill torchrun; sleep 10; pkill python`，按 TRIAL_ID / NODE_ID 过滤，写进 `init.py` 随训练自启
- **指纹**：退出码聚类（SIGTERM/SIGKILL 而非 OOM/异常）；同一 node 反复；`init.py` 内容变更
- 检测点：进程退出信号来源审计（auditd / cgroup events）+ 启动钩子文件基线

### 3.6 持久化层：checkpoint 当后门载体
- 手法：checkpoint 内嵌触发逻辑 / 加载路径挂钩子
- **指纹**：pickle opcode 异常（`GLOBAL`/`REDUCE` 指向 os/subprocess）；张量外的非预期键
- 检测点：反序列化白名单（safetensors / weights_only）+ checkpoint schema 校验

### 3.7 隐藏通道层：共享盘文本命令回执
- 手法：轮询 `.../barrier_vgpt/<trial>/in.<id>`，把文本当 shell 执行并回写结果，无外网
- **指纹**：训练进程派生出 shell 子进程；共享盘高频 stat/read；回执目录的写者与被读者非同一任务
- 检测点：训练进程子进程树监控 + 共享盘元数据访问审计（谁读了不该读的目录）

### 3.8 认知层：参会即侦察
- 手法：参加 debug 会议，据排查进展调整攻击
- **指纹**：无技术指纹——**只能靠流程**
- 对策：排查信息分级、假设与实验记录双人留痕、异常假设清单对"最小可解释集"收敛

## 4. 指纹防御体系（核心章节，按"改不动"的强度排序）

### 4.1 环境基线拍拓（一切的前提）
- 镜像 digest 固化；wheel `RECORD` 哈希清单；`pip freeze --all` 快照
- 文件树 Merkle 树（覆盖 `/usr/lib/python3*/site-packages`）
- 拍拓时机：镜像构建后、任务启动前、任务结束后各一次；差异入库
- **产出物**：一份可 diff 的 env manifest，替代"靠感觉觉得环境没变"

### 4.2 不可变运行时（让改动在物理上发生不了）
- 框架库走镜像内置，禁用任务期 `pip install` / 运行时写 site-packages
- 只读挂载 + 容器 rootless + 去掉容器内 sudo 能力（本案的 `sudo mv` 直接失效）
- 必要时 IMA / dm-verity 做启动期完整性度量

### 4.3 时间戳与 inode 取证（本文的技术核心）
- 讲清 Linux 三时间戳：atime/mtime 可写、**ctime 不可写**、btime 需文件系统支持
- 判据：`mtime < ctime`（内容比元数据旧 = 有人动过并回填）；同路径 inode 号变化；overlayfs upper 层白障
- 工具化：一条巡检脚本输出"mtime 早于 ctime 且近 30 天 ctime 有变的 site-packages 文件"

### 4.4 运行时完整性巡检
- 训练任务内周期性（如每 N step）抽样哈希已加载模块文件，不一致即告警
- 与基线 manifest 比对，而非与"上一次"比对（避免滚动污染）

### 4.5 审计与告警面
- auditd：`execve`（含 sudo）、`open` 带 `O_WRONLY` 指向 site-packages、`utimensat`/`chmod`/`chown` 落在系统库
- 共享盘：目录级写者审计；"训练任务读到了非自己 trial 目录"即高危
- 登录面：节点登录记录与任务 owner 对齐（本案 7-30 的突破口就是登录记录）

### 4.6 训练侧确定性断言（对抗"伪随机故障"）
- 同 seed 复跑：rank→样本 index 哈希必须一致
- 跨 rank 参数 diff：梯度同步后各副本应一致，发散即有人改了 optimizer / 通信
- 梯度范数独立复算；loss 曲线与 step 时长的联合异常聚类

### 4.7 进程与调度侧取证
- 退出信号来源（SIGTERM 由谁发）、cgroup OOM 与 pkill 的区分
- 失败按 (trial, node, rank, step) 四维聚合，找"只在某些 node"的模式

### 4.8 制品与权重
- checkpoint 反序列化白名单；权重入仓前 hash 校验（对 HuggingFace 官方 sha256）
- T5 权重类"混噪 + 恢复范数"的检测：范数一致但分布/KL 偏移，需与官方权重对拍

### 4.9 组织与流程（唯一能对抗 3.8 的一层）
- 共享目录写权限分域（本案根因之一：同组可写他人实验文件）
- 排查信息公开范围分级；关键假设与实验结果双人留痕、时间戳上链/不可改
- "环境无异常"必须由 manifest diff 支撑，不接受口头结论

## 6. 局限与误报（必须写，否则不可信）

- ctime 也会被正常运维动作改变（重装、镜像更新），需白名单窗口
- 大规模训练本身非确定性（fp8、异步通信、硬件降频），确定性断言要限定在"数据划分/采样式"确定性上
- 只读与审计都有性能开销，需量化（巡检频率、采样率）
- overlayfs 差异在重启后可能消失，需落盘留存
